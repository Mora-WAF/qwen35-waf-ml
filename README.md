# qwen35-waf-ml

A dataset pipeline, a Colab fine-tuning notebook and an offline decision policy for a **Qwen3.5-4B
WAF / NIDS classifier**. Given one sensor observation (an HTTP request, a network flow, or a request plus its
context), the model answers with a single JSON object: `{"threat_type": "<one of 41 classes>"}`. A separate
calibrated policy turns that answer into a recommendation (allow, block, abstain). Nothing here acts on live
traffic.

Defensive use only. All attack data is inert: public payload lists, public research captures, and synthetic
fixtures written by LLM workers. No traffic generators or exploit tooling are built.

## Taxonomy (41 classes, `config/taxonomy.yaml`)

| Domain | Classes |
|---|---|
| L7 injection | SQLi classic / obfuscated, NoSQLi, XSS reflected-stored / DOM-polyglot, RCE command injection, SSTI, XXE, deserialization, CRLF header injection, LDAP/XPath injection, CSV formula injection, malicious file upload (webshell) |
| L7 API / protocol | path traversal / LFI, SSRF (cloud metadata), HTTP request smuggling, GraphQL abuse, JWT auth bypass, BOLA/IDOR, BOPLA (mass assignment), BFLA (admin function probing), race condition (TOCTOU burst), open redirect / CORS, WebSocket / gRPC abuse |
| L7 AI / modern | LLM prompt injection, MCP / agentic tool abuse, prototype pollution, web cache poisoning |
| L4 network flow | SYN flood, UDP amplification, HTTP/2 rapid reset / CONTINUATION, slowloris / slow HTTP, credential stuffing / brute force, port scan, C2 beaconing, DNS tunnelling / exfiltration, TLS JA4 / user-agent spoofing |
| Benign | standard traffic, hard negatives (developer content), hard negatives (search text), high-rate legitimate traffic |

Each class has a scope, exclusions (the boundary rules between neighbours), the evidence it requires,
benign counterexamples and a precedence rule. Classes that need context to be decided (e.g. BOLA needs the
authorization context) abstain without it (`config/policy.yaml: required_context`).

## Quick start

Python 3.12 venv; system Python lacks the ML wheels. Always run modules as `.venv/bin/python -m ...`.

```bash
# local pipeline (requirements.lock pins the Colab training stack; the local packages are listed in its comments)
python3.12 -m venv .venv
.venv/bin/pip install transformers==5.17.0 pyyaml jsonschema pytest requests pyarrow pandas jinja2 huggingface_hub nbformat scikit-learn torch

# 1. pinned public sources -> ../raw_cache/ (outside the repo); CIC-Bell-DNS-EXF-2021 needs a manual browser
#    download (registration form), see its entry in config/sources.yaml
.venv/bin/python -m data_pipeline.ingest_public
# 2. payload seeds, quality rejects, near-duplicate clusters
.venv/bin/python -m data_pipeline.normalize
# 3. observed flows (CIC-IDS2017/2018, CIC-DDoS2019, CIC-Bell-DNS-EXF-2021, NF-ToN-IoT)
.venv/bin/python -m data_pipeline.flows
# 4. build the fast dataset (~43k records) and the robustness set
.venv/bin/python -m data_pipeline.build --quota-frac 0.25 --prefix fast_
.venv/bin/python -m data_pipeline.robustness
# 5. gate + quality reports
.venv/bin/python -m tests.validate_pre_colab --prefix fast_
.venv/bin/python -m eval.shortcut_audit --prefix fast_
.venv/bin/python -m eval.coverage --prefix fast_
.venv/bin/python -m eval.crs_oracle --prefix fast_
.venv/bin/python -m eval.baselines --prefix fast_
.venv/bin/python -m pytest -q tests
# 6. Colab bundle (refuses a failed gate) and notebook
.venv/bin/python -m training.make_bundle --prefix fast_
.venv/bin/python colab/make_notebook.py
```

Scenario records for classes without public seeds come from LLM workers (Claude Haiku subagents and Codex),
driven by job specs from `subagents/orchestrator.py` and the prompts in `subagents/prompts/`. Their raw outputs in
`data/jobs/out/` are irreplaceable: new rounds add new version files and never overwrite old ones.

## Training on Colab

`colab/Qwen3_5_4B_WAF_FineTune.ipynb` (generated by `colab/make_notebook.py`) does 16-bit rsLoRA fine-tuning
with Unsloth, CUDA GPUs only. It has two parts:

- **Part A** trains and exports the adapter. Settings at the top: `MODE` (`smoke` / `fast` / `full`), `DRY_RUN_STEPS`
  (e.g. 25 for a start-check with a full-run time estimate), `DRIVE_DIR` (set it for any run that can disconnect), `BATCH`
  (default: from GPU memory, T4 1 / L4 2 / A100-40 4 / 80 GB 8, effective batch 16), `SAVE_EVERY_MIN` (time-based
  checkpoints; resume only on the same GPU type).
- **Part B** runs after a kernel restart: reload check, continuation check (dry runs), and cell **B1s**, which scores every
  evaluation record with all 41 class log-probs into `SCORES_<mode>.jsonl`.

Upload `colab/colab_bundle_fast.zip`, run Part A, restart the runtime, run Part B, and download the report and scores.
Then calibrate locally:

```bash
.venv/bin/python -m eval.calibration reports/SCORES_fast.jsonl --write-policy
```

This fits the softmax temperature on `val_calib` and the decision threshold on `val_policy` (hard-negative false
intervention ≤ 1%), and freezes both into `config/policy.yaml`. Until then the policy abstains on everything
(shadow mode).

## Evaluation

Splits are assigned by **lineage group** (near-duplicate seeds, an attack and its benign twin, a capture campaign stay
together): train, `val_select` / `val_calib` / `val_policy`, test, and **test_unseen**. test_unseen holds out whole
scenario families, flow variants and seed or capture sources that never appear in training; it is the score that
matters.

The bars a fine-tuned model must beat (`reports/baselines.json`): a char 3–5-gram TF-IDF + linear SVM on the same
serialized telemetry, and the OWASP CRS paranoia-level-1 regexes (HTTP only, attack vs benign).

## Labels and their limits

- Observed flows and CRS fixtures carry source labels, kept only where the measured telemetry can show them
  (`data_pipeline/flows.py: CONSISTENT`).
- Everything else rests on generator intent plus review: blind same-model review (Haiku) on every LLM record, and
  cross-model samples (Codex `gpt-6.1-sol`, Gemini Flash) on the weak classes. Agreement filters noise; it is not ground truth.
- Several classes are synthetic-only (SYN flood, UDP amplification, HTTP/2 rapid reset and all the scenario classes), and
  the observed captures come from lab testbeds. Deployment needs evaluation on your own traffic.
